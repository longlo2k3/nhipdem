# Domain docs

Use a single-context layout:
- `GLOSSARY.md` at the project root.
- Architecture decisions in `docs/adr/`.

Before exploring the project, read the glossary and relevant decisions.
If these documents do not exist, continue; create them when a term
or design decision needs to be recorded.

Use the glossary's terminology when naming domain concepts.
Explicitly flag proposed changes that conflict with a recorded decision.
